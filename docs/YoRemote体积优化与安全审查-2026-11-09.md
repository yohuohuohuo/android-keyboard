## 安全审查结果

### 需要知情处理的现有边界

1. **[P2，输入隐私，已确认配置] 普通文本输入不提供凭证保护。** `VirtualKeyboard.kt:71–89` 使用普通 `OutlinedTextField` 和 Ascii 键盘，没有密码遮挡/专用敏感输入模式，Activity 未启用 `FLAG_SECURE`。在此输入密码或其他秘密时，所选输入法可接触输入，屏幕、任务预览或已获屏幕录制权限的软件可能看到内容。未发现应用自己将文本持久化或上传；关闭自动纠错不能阻止第三方输入法读取。建议日常使用时不输入敏感凭证；若业务需要密码输入，单独设计可信输入法、屏幕保护和状态清理方案，本轮不擅自改变产品。

2. **[P2，设备元数据隐私，源码推断] 系统备份可能带走设备地址和设置。** 主清单 `allowBackup=true`；`backup_rules.xml` 与 `data_extraction_rules.xml` 没有排除 DataStore。`SettingsDataStore.kt:277–304` 持久化收藏设备地址和自动连接地址，其他写入为界面与遥控偏好。这些文件可能进入系统备份或迁移；触发取决于设备、备份开关和备份传输实现，本轮未实际触发云备份。没有输入文本写入 DataStore 的路径。若要求元数据只留本机，最小后续方案是对相应文件添加备份/迁移排除并验证恢复行为。[Android 备份规则](https://developer.android.com/identity/data/autobackup)。

3. **[P2，CI 供应链，条件性风险] 上游 GitLab 流水线直接执行可变远程脚本。** `src/.gitlab-ci.yml:28` 从 GitLab `raw/main/installer` 下载并 `| bash`，SDK 下载也未声明内容校验；根 GitHub 工作流的第三方 Action 使用版本标签。若未来在带签名材料的 CI 中执行，远端内容或标签被恶意改变可能导致密钥泄露或产物污染。当前本地 `build.sh + gradlew` 不运行该 GitLab 脚本，本轮没有执行远端流水线，因此不据此判定当前 APK 已污染。启用相应 CI 前应固定可信提交/镜像摘要并校验下载内容；本轮只报告，不扩大改造。

上述问题没有建立当前 APK 的高危外部利用路径，也不是木马实证。未新增网络权限或扩大组件暴露范围。

### 入口、权限与外部输入

- 检查了主清单、依赖合并清单、Manifest merger 来源和最终 APK 二进制清单，不能仅凭源码主 Manifest 判断。
- 优化前后权限逐项一致：旧系统的 Bluetooth/Admin 和定位权限限到 API 30；新系统 Bluetooth Connect/Scan（`neverForLocation`）、通知、connectedDevice 前台服务；依赖引入 `WAKE_LOCK`、`ACCESS_NETWORK_STATE`、`RECEIVE_BOOT_COMPLETED` 和 signature 级动态 receiver 私有权限。**没有 INTERNET**；`ACCESS_NETWORK_STATE` 只是网络状态读取，不授予网络通信权限。
- 无录音、摄像头、短信、联系人、全文件访问、悬浮窗、无障碍服务、设备管理员或应用安装权限。没有更新下载器或独立远控接收端。
- 无特权保护的对外应用入口只有启动 MainActivity；它不解析外部 HID 指令或文本。HID Service、通知控制 Receiver、产品 Widget Receiver 不导出。
- Tile 受 `BIND_QUICK_SETTINGS_TILE` 保护；依赖导出的 RemoteViews、JobService、诊断和 ProfileInstaller 组件分别受 `BIND_REMOTEVIEWS`、`BIND_JOB_SERVICE` 或 `DUMP` 保护。Startup provider 和其余内部组件不导出；没有发现无权限导出的任意控制入口。
- 动态蓝牙扫描/状态广播仅处理系统 Bluetooth action；输入数据来自系统 BluetoothDevice Parcelable。待连接地址从已配对设备列表或经过 MAC 格式检查的显式输入取得。未发现广播/Intent 内容进入 shell、动态类加载或任意反射的路径。
- 通知、Tile、Widget 都使用显式 MainActivity、`ACTION_MAIN + NEW_TASK | CLEAR_TOP | SINGLE_TOP`；使用 PendingIntent 的位置保持 `FLAG_IMMUTABLE`，通知控制 Intent 指向内部 Receiver 并限定动作集合。外部入口和旧 PendingIntent 身份区分的现有测试通过，但本轮未逐个操作这三种真实入口。

### 文本、触摸与蓝牙数据流

- 文本：普通输入框 → `RemoteViewModel` 内存中的 draft/lastAttempt → `RemoteUseCase.sendTextReport` → 布局字符到 HID 键值 → `BluetoothHidCore.sendReport` → Android `BluetoothHidDevice`。触摸、鼠标、遥控数据也直接变为 HID 报文。
- 没有发现输入文本写入文件、DataStore、日志、剪贴板或 HTTP 的代码；草稿和待核对原文保存在 Activity 级 ViewModel 内存，模式/页面等非文本 UI 状态使用 `rememberSaveable`。退出到后台不等于进程内文字已立即销毁，不能把它当作秘密擦除工具。
- 日志路径仅见扫描 Receiver 重复注销错误和 DataStore IO 异常堆栈；未发现输入内容日志。通知包含连接设备名称和遥控动作，不包含输入文本；锁屏上显示设备名取决于通知系统设置。
- HID 控制配对设备是产品预期能力；没有向非蓝牙远端传输输入的应用路径。蓝牙配对、重连和协议栈安全依赖系统及用户选择的目标，不能据此保证配对设备或系统未受入侵。
- 前台服务使用 `connectedDevice` 类型，维护通知，停止/销毁时注销 HID、清理任务并释放输入；任务移除时停止服务。权限检查存在，但检查与系统调用之间的权限撤销时序、OEM 异常路径没有在本轮做压力验证。
- 未发现运行时下载 DEX、DexClassLoader/PathClassLoader、自更新、`Runtime.exec`、ProcessBuilder、shell 命令、自定义原生代码或可疑编码载荷。唯一应用层反射为用户取消配对时调用系统 `BluetoothDevice.removeBond`，方法名固定且异常返回失败。最终 DEX 方法引用核对也未见上述动态加载器或进程执行 API；有标准 `Class.forName/getMethod/invoke` 与 `System.loadLibrary`，与框架初始化/平台兼容及两类 AndroidX 原生库相符，不能把整个依赖内部反射都称为恶意执行。完整方法引用及组件核对记录为 `final-dex-reference-audit.json`。
- 设置/第三方许可页面的固定 HTTPS 链接只有用户点击才交给外部浏览器，不附带输入文本。无 INTERNET 不等于输入法或 Android 系统永远不会联网，备份和输入法边界仍按上文处理。

## 重放命令

`build.sh` 拒绝覆盖已有目标，需使用一个尚不存在的新目录；下面的目录名仅为示例：

```sh
bash build.sh artifacts/yoremote-0.1.9-rebuild
cd artifacts/yoremote-0.1.9-rebuild
export JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'
export ANDROID_HOME=/Users/qiuyupan/Library/Android/sdk
export ANDROID_USER_HOME=/Users/qiuyupan/git_workspace/android-keyboard/artifacts/.android-home
export GRADLE_USER_HOME=/private/tmp/android-keyboard-gradle-01a1ba37
sh ./gradlew --no-daemon --no-build-cache testDefaultDebugUnitTest assembleDefaultDebug assembleDefaultOptimized assembleDefaultDebugAndroidTest
sh ./gradlew --no-daemon --continue lintDefaultDebug lintDefaultOptimized
```

最后一条 lint 命令预计因上述既有错误失败，应保留真实结果。不要运行会删除现有补丁的 `generate.sh` 来替代重放，也不要在脏 `src` 中重复应用补丁。

最少后续真机步骤：保持已安装优化包，在目标 Mac 空白编辑器重复检查英文/拼音与按键/鼠标；有草稿时分别经通知、快捷设置、Widget 返回，核对草稿/待核对原文仍在；测试按键按住时切页、后台、断连与权限撤销，确认不粘键且不自动重发。不要在密码框、终端或其他有动作副作用的位置做输入测试。
