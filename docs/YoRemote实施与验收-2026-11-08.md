## 本次改动

1. 四个平级页面，底部顺序固定为“触控板、键盘、快捷输入、遥控”，默认触控板，无滑动切页，复用同一连接、HID 服务和 ViewModel。更多菜单保留设置、帮助、扩展按键与断开。
2. 触控板填满剩余内容；滚动栏 56dp 宽、底部鼠标键 56dp 高。鼠标手势、速度和报告参数保持原实现；公共按钮增加取消/销毁释放并使用最新回调。
3. 完整键盘取消半屏限制，常用键五行，功能层保留 F1–F12、Esc 及左右修饰键等原键位；标签为 Cmd / Option。主动横屏只作用于键盘页，离页恢复原方向策略。极小窗口保留滚动兜底，不无限缩小按键。
4. 快捷输入独立成页。手机编辑英文/拼音后发送，Mac 的日常中文输入法组字和选词；普通发送与 IME 发送均不附加 Enter。保留空格、方向、退格、回车等候选控制键；IME 和系统安全区纳入布局。
5. 文本发送预检整个字符串，不支持字符不发送任何前缀；重复提交被拒绝，失败或取消保留草稿。只有所有报告提交完成，才按原设置清空，而且不清掉发送期间新编辑的草稿。
6. 保留当前一次未完成/待核对的发送原文。若用户已编辑成新草稿，另显示原提交文本；仅留在当前 Activity 的内存，不写入输入日志、不保存完整历史。断线导航出栈后重连仍保留，App 进程结束不保证保留。
7. Direct Input 辅助模式使用同一映射和发送任务。一次 IME 编辑包含多个字符时逐个发送；发送中再编辑会保留新草稿并退出辅助模式，不增加自动队列或后台重放。该模式的模拟测试单列，不能外推为所有手机输入法均已验证。
8. 切页、切功能层、旋转、后台、断线和离页均中止文本任务并尝试释放键盘、鼠标、消费控制。epoch 防止旧任务晚到的释放影响新页面；断开服务前也尝试释放。通知“断开”现在请求停止前台 HID 服务；静态调用链经 onDestroy 到 unregisterApp（蓝牙权限仍有效时）。模拟测试验证停止请求，实际注销仍需手机确认。

未实现 Unicode Hex Input、汉字直传、Mac 接收端、剪贴板同步、新联网能力或输入法引擎。蓝牙报告受理不代表 Mac 已显示文字。

## 漏键证据

原 `AdvancedKeyboard` 在按下/抬起时只修改 Compose 状态，再依赖 `LaunchedEffect` 发报告。真实组件的受控帧测试复现了同帧短按缺少报告、连续同键报告数不足；原 F1 测试同时暴露文字显示类型被当作修饰键的问题。

最小修复在按下/抬起回调内直接、按序生成报告，Compose 状态不再转发瞬时事件。修饰键采用显式语义与按位组合，避免 F7 与右 Option 字节值重叠导致误分类。未增加全局延迟或按键重发，原文本按下/释放各 25ms 保持。

证据在 `artifacts/yoremote-evidence/`：

- `keyboard-red-3.log` 和 `keyboard-original-red-results/`：旧实现同帧/重复键失败。
- `input-red.log` / `input-green.log`：事件、F1 与文本报告 RED→GREEN。
- `shutdown-feedback-red.log`：通知断开不停止服务、编辑新草稿仍显示旧成功提示的失败用例。
- `snackbar-red.log`：按键失败提示被状态清理提前取消；修复后提示持续显示。
- `review-red.log`：独立复核的发送快照、真实导航断线草稿、Direct 忙态问题的失败用例。
- `direct-controlled-original-red.log`：冻结发送协程时，恢复旧 readOnly 行为会丢掉后续编辑；修复后同用例通过。

这些证据确认并修复了代码层报告生成缺陷；用户手机上的偶发漏输入仍需用下面的真机用例验收，不能据此宣称真机问题已全部解决。

## 手机 / Mac 验收（待执行）

先记录：手机型号、Android 版本、Mac 型号、macOS 版本、Mac 输入法和键盘布局。

1. **轮流启用。** 保留原版/旧测试版，在其通知或菜单点击断开并确认服务通知消失，再启动 YoRemote。必要时用 `adb shell dumpsys bluetooth_manager` 核对当前 HID 应用/注销状态；仅切后台不表示注销。不要同时注册两个 App、不清除其他版本数据或系统配对记录。反向切换也按此流程。
2. **新身份与更新。** 安装本 APK，应与原版/旧包并列，显示 YoRemote；首次独立授权。后续相同新包名和签名可用 `adb install -r artifacts/yoremote-0.1.0-debug.apk` 覆盖更新。检查通知、快捷设置、桌面组件打开正确版本。
3. **矩阵 ABC。** Mac 文本编辑新建普通文档、切 ABC；轻点 `abc123`、`aaaaaaaaaa`、`ababababab`，再用慢按作对照。固定 A 100 次比较手机点击数、生成报告数和 Mac 字符数，不能只看接口受理。验证 Shift+A、Cmd+C/V、Option、F1、F7、Esc、退格、方向和回车。
4. **释放。** 按住 Shift/Cmd/鼠标键时切页、切功能层、旋转、进入后台、断线；Mac 不应残留按住状态。断线无法证明释放已送达；检查本地状态归零、重连无离线累计和自动重放。
5. **普通快捷输入。** ABC 下发送 `abc123`；Mac 系统拼音下手机编辑 `nihao` 后发送，Mac 出候选，再用空格/数字/方向/回车选“你好”。普通发送/手机 IME 发送不附加 Enter。汉字/emoji 等不支持字符应提示、保留原文，不能只发送可映射前缀。
6. **草稿与中止。** 编辑后切 Tab、旋转、收起/弹出手机键盘；草稿不丢，四 Tab 和发送入口可达。长固定样例发送中切页/后台/断线，原文与新编辑草稿均可核对，Mac 可能已收到部分内容；重连不自动继续。忙时不重复提交。
7. **Direct 单列。** 辅助模式分别测试单字母、多字符一次 IME commit、发送中继续编辑、退格、物理键盘和输入法候选提交。确认忙态保留新草稿并退出辅助模式，不把普通拼音发送成功外推为该模式全面正常。
8. **鼠标与布局。** 回归移动、单/双/三指点按、双指滚动、鼠标键、拖动和陀螺仪（如启用）。横竖屏与手机手势安全区下检查控制区域、底栏、功能层，离开主动横屏的键盘页应恢复原方向策略。

本轮没有连接手机/Mac，也未安装 APK 到真机；上述项目仍待用户现场验收。不会因等待真机而停止本地代码、构建和证据交付。
